# 宠物领养管理系统 —— 在另一台电脑运行指南

适用范围：把本项目从当前电脑搬到另一台 Windows 电脑上运行（开发调试 / 现场演示）。
技术栈：Spring Boot 3.2.5（JDK 17）+ MyBatis-Plus + MySQL 8/9 + Vue 3.4 + Vite 5 + Element Plus。

---

## 0. 先看这张清单

| 软件 | 版本要求 | 用途 | 验证命令 |
| --- | --- | --- | --- |
| JDK | 17（必须） | 运行后端 | `java -version` |
| Maven | 3.9.x（用 IDEA 可免装） | 编译后端 | `mvn -v` |
| MySQL | 8.0 及以上 | 数据库 | 服务正常运行，端口 3306 |
| Node.js | 18 LTS 及以上（Vite 5 要求） | 运行前端 | `node -v`、`npm -v` |
| IDEA | 任意版本 | 打开后端（可选） | — |
| VSCode | 任意版本 | 打开前端（可选） | — |

固定端口：后端 **8080**（上下文路径 `/api`），前端 **5173**。

### 日常启动速查（装好环境后，每次开工就这三步）

| 步骤 | 操作 | 成功标志 |
| --- | --- | --- |
| 1 | 确认 MySQL 服务为「正在运行」 | 3306 端口可连 |
| 2 | 启动后端：IDEA 里运行 `PetApplication`，或命令行 `java -jar target\pet-adopt-1.0.0.jar` | 控制台出现 `Started PetApplication` |
| 3 | 启动前端：`cd /d D:\...\frontend` 然后 `npm run dev` | 出现 `Local: http://localhost:5173/` |

> 只有**第一次**在新电脑上（或删过 `node_modules` / `target` 后）才需要装依赖：后端 `mvn clean package -DskipTests`，前端 `npm install --legacy-peer-deps`。装过一次以后不用再装。

## 1. 拷贝项目（只拷源码，不要拷依赖）

把整个 `宠物领养管理系统` 文件夹拷到新电脑，例如仍放在 `D:\Download\A毕业设计全套\宠物领养管理系统`。

**拷贝前请在新电脑上删掉下面这些目录**（体积大，且含本机编译的二进制，跨电脑会报错）：

- `frontend\node_modules` —— 必须删，里面 `esbuild` / `sass` 是按本机平台编译的，换电脑会报 "Cannot find module" 或平台不匹配
- `frontend\dist` —— 打包产物，用不到
- `pet-server\target` —— 编译产物，重新打包即可
- `.idea`、`frontend\.vscode` —— 编辑器配置，新电脑会重建
- `pet-server\server.log`、`backend_run.log`、`backend_run.err`、`frontend\dev*.log` —— 旧日志

真正需要拷的是：`pet-server\src`、`pet-server\db`、`pet-server\pom.xml`、`frontend\src`、`frontend\public`、`frontend\index.html`、`frontend\package.json`、`frontend\package-lock.json`、`frontend\vite.config.js`、`docs`。

## 2. 安装环境

1. **JDK 17**：安装后配置 `JAVA_HOME`，`Path` 追加 `%JAVA_HOME%\bin`。命令行执行 `java -version` 应显示 17。
2. **Maven 3.9**（若用 IDEA 自带 Maven 可跳过）：解压到如 `D:\Maven\apache-maven-3.9.x`，新建 `MAVEN_HOME`，`Path` 追加 `%MAVEN_HOME%\bin`；`mvn -v` 能看到版本即成功。
3. **MySQL 8.0+**：安装时端口保持 3306，记下 root 密码（安装完在「服务」里确认 MySQL 服务为“正在运行”）。建议装 Navicat 或 SQLyog 方便执行脚本。
4. **Node.js 18 LTS+**：安装时勾选自动配置环境变量，`node -v`、`npm -v` 有版本号即成功。

## 3. 建库并导入数据

### 3.1 建库建表并导入演示数据（必做）

用 Navicat / SQLyog 打开 `pet-server\db\schema.sql`（db 目录下唯一的 SQL 脚本），整段执行即可。脚本会自动完成：

- 创建数据库 `pet_adopt`（utf8mb4）
- 创建 7 张表：`sys_user`、`user_info`、`pet`、`adopt_apply`、`adopt_record`、`return_visit`、`notice`
- 插入预置管理员：用户名 `admin`，密码 `123456`（BCrypt 加密存储）
- 导入演示数据：16 个普通用户、6 只宠物、13 条申请、7 条领养记录、5 条回访、1 条公告

命令行方式（在 MySQL 的 bin 目录下）：

```bat
mysql -uroot -p < D:\...\pet-server\db\schema.sql
```

> 注意：脚本里带 `DROP TABLE IF EXISTS`，**只用于新电脑或空库；在已有数据的库上执行会清空原有数据**。

### 3.2 带上演示数据（建议做，否则新电脑是空库）

新库只有管理员账号，没有任何宠物和公告，演示时列表、图表都是空的。**在旧电脑上先导出一份数据**（旧电脑需先启动 MySQL 服务）：

```bat
cd /d D:\MySQL\mysql-9.6.0-winx64\bin
mysqldump -uroot -p你的密码 --databases pet_adopt --no-create-info --complete-insert --skip-comments > D:\pet_adopt_data.sql
```

把 `pet_adopt_data.sql` 拷到新电脑，在**建表之后**导入：

```bat
mysql -uroot -p你的密码 pet_adopt < D:\pet_adopt_data.sql
```

只用 Navicat 也可以：右键库 → 转储 SQL 文件 → 仅数据。

若不想导数据，就手动在「宠物档案」里录 3~5 只宠物、发 1 条公告，工作台的图表才有内容。

## 4. 改数据库密码（最容易卡住的一步）

打开 `pet-server\src\main\resources\application.yml`：

```yaml
spring:
  datasource:
    username: root
    password: ${DB_PASSWORD:1234}    # ← 冒号后面就是默认密码
    url: jdbc:mysql://localhost:3306/pet_adopt?...
```

把 `1234` 改成新电脑 MySQL 的 root 密码，例如：

```yaml
    password: ${DB_PASSWORD:123456}
```

也可以用环境变量覆盖（不改文件）：系统环境变量里新建 `DB_PASSWORD`，值为实际密码。

> 数据库名称 `pet_adopt`、端口 `3306` 与实际不一致时，同步改 `url` 这一行。

## 5. 启动后端

### 方式 A：用 IDEA（推荐）

1. `File → Open`，选择 `pet-server` 目录（能识别 `pom.xml` 的那个）。
2. 等 Maven 下载依赖（首次需要几分钟，右下角有进度）。
3. `File → Project Structure → Project SDK` 选 **17**；`Settings → Build Tools → Maven` 指向本机 Maven。
4. 打开 `src\main\java\com\pet\adopt\PetApplication.java`，点绿色三角运行。
5. 控制台出现下面两行即成功：
   - `Tomcat started on port(s): 8080 (http)`
   - `Started PetApplication in x.x seconds`

> 若报 `找不到 getter/setter` / `变量 xxx 未在默认构造器中初始化`，是 Lombok 没生效：`Settings → Plugins` 确认 Lombok 插件**已启用**，并在 `Settings → Build → Compiler → Annotation Processors` 勾选 `Enable annotation processing`。

**IDEA 项目模型损坏时的修复（重要）**

出现「没有为模块 'pet-adopt' 指定 JDK」「外部库为空、所有 import 报红、构建 100 个错误」这类现象，说明模块没被 Maven 接管（多数是删过 `.idea` 又手工补过配置文件导致）。**不要手工改 `.xml` / `.iml`**，按下面重置：

1. `File → Exit` 完全退出 IDEA（不是关窗口）
2. 删除 `pet-server\.idea` 整个目录，以及项目根下所有 `*.iml`
3. 重新打开 IDEA，欢迎页 `Open` 选 **`pet-server` 这一层**（不要选外层 `宠物领养管理系统`）
4. 等右下角 Maven 同步进度条走完；提示选 JDK 时选 **17**
5. 成功标志：`外部库` 里能看到 `Maven: org.projectlombok:lombok...`、`spring-boot...`、`mybatis-plus...`，代码不再报红

> 重置只删编辑器配置，`src`、`pom.xml`、`db` 里的代码和数据一行都不会动。

### 方式 B：命令行（不装 IDEA 也能跑）

```bat
cd /d D:\...\pet-server
mvn clean package -DskipTests
java -jar target\pet-adopt-1.0.0.jar
```

> 用旧 jar 直接跑的话，务必先改好 `application.yml` 再 `mvn package`，否则打的还是旧配置。

### 验证后端

浏览器访问：<http://localhost:8080/api/test>

返回 `{"code":401,"msg":"未登录或登录已过期","data":null}` 是**正常**的——`/api/test` 已被登录拦截器接管，只要不是连接被拒或 500，就说明后端与路由都正常。
要进一步确认链路，直接打开管理端登录页用 `admin / 123456` 登录即可；若这里就报 500，说明数据库没连上，回第 3、4 步检查。

## 6. 启动前端

打开命令行：

```bat
cd /d D:\...\frontend
npm install --legacy-peer-deps
npm run dev
```

看到 `Local: http://localhost:5173/` 即成功。

> **`--legacy-peer-deps` 不能省**：`package-lock.json` 锁定的 `vue-router 4.6.4` 声明要求 `vue ^3.5.0`，而本项目锁定 `vue 3.4.38`，直接 `npm install` 会报 `ERESOLVE could not resolve` 装不上；加这个参数按锁文件安装即可，实际运行没有问题。本机 Node 为 v22，同理。

`npm install` 慢时先换源：

```bat
npm config set registry https://registry.npmmirror.com
```

前端把 `/api` 请求代理到 `http://localhost:8080`（见 `vite.config.js`），所以**后端必须先启动**，否则页面能打开但数据全是报错。

## 7. 访问与验收

| 端 | 地址 | 账号 |
| --- | --- | --- |
| 管理端 | <http://localhost:5173/admin/login> | admin / 123456 |
| 用户端 | <http://localhost:5173/user/login> | 自己注册，或用旧数据里的用户 |
| 用户端首页 | <http://localhost:5173/user/home> | 可游客访问 |

演示前建议按这条线走一遍（也是报告里的验收流程）：

1. 管理端登录 → 工作台看到 4 个指标卡片、趋势图、类型饼图
2. 宠物档案新增一只宠物
3. 用户端注册 → 登录 → 宠物列表 → 详情 → 提交领养申请
4. 管理端「领养申请」审核通过 → 「领养记录」出现新记录，「宠物档案」里该宠物状态变已领养
5. 「回访管理」新增回访 → 登记结果 → 状态变已完成
6. 用户端「我的申请」状态变已通过

## 8. 常见报错对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Communications link failure` / `Access denied` | MySQL 服务没启动 / 密码不对 | 「服务」里启动 MySQL；核对第 4 步密码 |
| `Unknown database 'pet_adopt'` | 没执行建表脚本 | 执行 `db\schema.sql` |
| 页面能打开但接口全 404 | 后端没启动，或 context-path 不是 `/api` | 确认 8080 已启动、`application.yml` 里 `context-path: /api` |
| 端口被占用（8080 / 5173） | 旧进程没关 | `netstat -ano | findstr :8080` 找到 PID，任务管理器结束；或改端口（改 5173 需同步改 `vite.config.js`） |
| `Cannot find module 'esbuild'` 之类 | 拷了旧 `node_modules` | 删掉 `node_modules` 重新 `npm install --legacy-peer-deps` |
| `npm error code ERESOLVE` / `could not resolve vue-router@4.6.4` | vue-router 4.6.4 要求 vue 3.5，本项目锁定 vue 3.4.38 | 用 `npm install --legacy-peer-deps`，不要改 vue 版本 |
| `没有为模块 'pet-adopt' 指定 JDK` / `外部库` 为空 / 构建 100 个错误 | IDEA 项目模型损坏，模块没被 Maven 接管 | 按第 5 节「IDEA 项目模型损坏时的修复」重置 |
| `'vite' 不是内部或外部命令` | `node_modules` 不存在（被精简掉了） | 在 `frontend` 目录执行 `npm install --legacy-peer-deps` |
| 中文乱码 / 时间不对 | 库不是 utf8mb4 / 时区 | 建库时用 utf8mb4；连接串已带 `serverTimezone=Asia/Shanghai` |
| 宠物图片不显示 | 头像存的是外链地址 | 需联网，或在「宠物档案」改成本地可访问的图片地址 |

## 9. 打包成可交付的 jar（可选）

```bat
cd /d D:\...\pet-server
mvn clean package -DskipTests
```

产物：`pet-server\target\pet-adopt-1.0.0.jar`，拷贝这个 jar + 一个新的 `application.yml`（放在 jar 同级 `config` 目录可覆盖内置配置）即可在只装了 JDK 的机器上运行。

前端若要脱离 Node 运行，可 `npm run build` 生成 `dist`，用任意静态服务器（如 `npx serve dist`）托管；但 `dist` 里的 `/api` 需要由服务器反代到 8080，答辩演示建议直接用 `npm run dev`，最省事。
