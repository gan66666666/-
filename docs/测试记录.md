### 联调前检查结论

| 检查项 | 检查方式 | 结论 |
| --- | --- | --- |
| 后端可启动（8080，context-path `/api`） | `mvn clean package` 后 `java -jar` 启动，日志出现 `Tomcat started on port 8080 (http) with context path '/api'` | 通过 |
| 前端可启动（5173） | `npm run dev` 启动，`GET /` 返回 200 | 通过 |
| vite 代理指向正确 | `GET http://localhost:5173/api/pet/page` 返回 `code=200`，请求被转发到后端 | 通过 |
| 管理端 / 用户端 token 键不冲突 | 管理端 `utils/auth.js` 存 `adminToken`，用户端 `utils/userAuth.js` 存 `userToken`；同一浏览器同时登录两端，`adminToken` 与 `userToken` 互不覆盖 | 通过 |
| 401 分流跳转 | 管理端 `api/request.js` → `/admin/login`；用户端 `api/userRequest.js` → `/user/login` | 通过 |
| 路由守卫 | `/admin/**` 未登录跳 `/admin/login`；`/user/apply`、`/user/myapply`、`/user/profile` 未登录跳 `/user/login`；`/user/home`、`/user/pets`、`/user/notices` 游客可访问 | 通过 |

## 八、缺陷记录

### 8.1 前序步骤已修复的问题（沿用）

| 编号 | 问题现象 | 原因 | 修复方式 |
| --- | --- | --- | --- |
| D-01 | 前端提交 `LocalDateTime` 类型字段时后端报日期格式错误 | 前端传的是 `yyyy-MM-dd HH:mm:ss` 字符串，后端未加兼容反序列化器 | 新增 `util/LocalDateDeserializer.java` / `LocalDateTimeDeserializer.java`，用 `@JsonDeserialize(using=...)` 兼容纯日期、带空格时间与 ISO 时间三种格式 |
| D-02 | `PUT` 类接口缺少 id 校验，提交空 id 时抛空指针 500 | Service 层直接 `selectById(null)` | 统一在 Service 入口补「xxxID不能为空」的业务校验（公告、宠物、回访、申请均已补齐） |
| D-03 | 新增接口允许前端指定主键，可能造成主键冲突与数据错乱 | 直接把 DTO 的 id 透传进实体 | 新增场景统一 `setId(null)`，主键一律由数据库自增生成 |
| D-04 | 后台页面打开/关闭弹窗时整页布局抖动（表格、侧栏位置跳动） | 页面级滚动条增减 + Element Plus 弹层动画自带 `translateY` 位移 | 页面级禁止滚动、`ElMain` 自己滚动并加 `scrollbar-gutter: stable`、抵消 `body.el-popup-parent--hidden` 的 padding 补偿、换掉弹层位移动画；详情弹窗改为用列表行数据回填，打开弹窗不发请求、不加 `v-loading` |
| D-05 | 宠物类型饼图出现「猫咪 0%」这类无效图例 | 0 计数类型也进了图例和扇区 | 过滤掉 `value<=0` 的类型再画图，图例百分比按有效总数计算 |
| D-06 | 注册接口请求被旧进程拦截，注册无响应 | 旧的后端进程仍占用 8080 端口，新代码未生效 | 结束占用端口的旧进程后重新打包启动，联调前确认端口与进程归属 |

### 8.2 本轮联调新发现并修复的问题

| 编号 | 问题现象 | 原因 | 修复方式 | 影响范围 |
| --- | --- | --- | --- | --- |
| D-07 | 接口提交超长文本时返回 `500 系统异常，请稍后重试`，用户看不懂是哪一项填错 | 数据库字段是 `VARCHAR(n)`，后端只校验了必填没校验长度，超长直接被 MySQL 拒绝变成 SQL 异常 | 新增 `util/ValidationUtil.java`（按字段实际列宽统一拦截，返回 `code=400` + 「XX 长度不能超过 N 个字符」），并在宠物、公告、领养申请、回访、用户注册/改资料 5 个 Service 中接入 | 宠物名称/类型/品种/性别/图片地址/健康状况、公告标题与内容、申请人姓名/电话/宠物名/领养理由、驳回原因、回访宠物名/领养人/内容、用户名/昵称/手机号/密码/地址 |
| D-08 | 用户端注册页与个人中心的「昵称」「手机号」输入框没有长度限制，用户可以输入超长内容并触发后端错误 | 前端表单未设置 `maxlength`，与数据库列宽不匹配 | 注册页昵称加 `maxlength=20`、手机号加 `maxlength=11`；个人中心昵称加 `maxlength=20`、手机号加 `maxlength=11` | `frontend/src/views/user/register/index.vue`、`frontend/src/views/user/profile/index.vue` |
| D-09 | 联调时 `PUT /api/visit` 报 `405 Request method 'PUT' is not supported`，登记回访结果无法保存 | `target/` 目录是旧的增量编译产物，`ReturnVisitController` 里仍是 `@PutMapping`（映射到 `/visit`）的老字节码；且运行中的后端进程占用 `pet-adopt-1.0.0.jar`，导致 `mvn package` 无法覆盖重打包（`Failed to delete ... pet-adopt-1.0.0.jar`），新代码始终没生效 | 停掉占用 jar 的后端进程后执行 `mvn clean package -DskipTests` 全量重编译重打包，再启动新 jar；确认 `javap` 可见 `@PutMapping` 与类级 `@RequestMapping("/visit")` 正确映射 | 后端构建与启动流程 |

### 8.3 本轮检查未发现问题的项目

- `frontend/vite.config.js` 的 `/api` 代理指向 `http://localhost:8080`，转发正常；
- 管理端 `adminToken` 与用户端 `userToken` 存储键互不冲突，同一浏览器可同时登录；
- 两端 401 分别跳 `/admin/login` 与 `/user/login`，没有串端；

- 业务闭环（浏览 → 注册 → 登录 → 申请 → 审核 → 领养记录 → 宠物状态 → 回访 → 公告置顶）字段名、状态码与页面跳转全部一致，未发现字段错配或状态码不一致。

### 9.2 结论

1. **系统功能完整**。用户端与管理端的完整业务闭环跑通：游客浏览 → 注册 → 登录 → 提交领养申请 → 管理员审核 → 自动生成领养记录并把宠物置为「已领养」→ 用户端回看状态 → 创建并登记回访 → 发布置顶公告并置顶展示，各环节的接口字段名、状态码与页面跳转完全一致。
2. **权限控制有效**。未登录 401、跨端调用 403、伪造令牌 401、前端路由守卫四层拦截均按预期工作，管理端与用户端令牌互不串用。
3. **本轮共发现并修复 3 个缺陷**（D-07 超长文本返回 500、D-08 前端输入框缺长度限制、D-09 打包产物与源码不一致导致接口 405），修复后回归全部通过。
4. **修复后整体通过率 100%（61/61）**，系统达到课程设计的功能验收标准，可进入文档编写与答辩演示阶段。
